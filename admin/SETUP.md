# ハモソ管理画面：認証APIの設定手順

## 目的と現在の範囲
このWorkerは年度共通パスワードをサーバー側で照合し、署名付きセッショントークンを発行します。ログイン試行はIPごとに15分で最大5回までに制限します。お知らせ・演奏会情報、画像アップロード、サイト情報（活動紹介・写真URL・動画URL・SNS・入会案内・活動予定）の管理APIを含みます。

## Cloudflare側の設定（ブラウザのみ）
1. Cloudflareアカウントを作成し、Workers & Pagesから新しいWorkerを作成します。
2. このリポジトリの `admin/worker.js` の内容をWorkerのコードエディターに貼り付けて保存・デプロイします。
3. WorkerのSettings / Bindingsで、KV namespaceを作成し、変数名 `LOGIN_LIMITS` でバインドします。
4. WorkerのSettings / Variables and Secretsで、次の2つを **Secret** として登録します（通常のText変数ではなくSecret）。
   - `ADMIN_PASSWORD`: 年度用の強いパスワード。長くランダムなもの（推奨20文字以上）にし、チャットやリポジトリに書かないでください。
   - `SESSION_SECRET`: 別のランダムな秘密値。少なくとも32文字。年度更新時はこれも変更して旧セッションを無効化します。
5. WorkerのURL（例：`https://任意の名前.あなたのサブドメイン.workers.dev`）を控えます。実際のURLはCloudflareが発行したものを使います。

## 画像の保存・削除
- 管理画面からアップロードした画像は、ブラウザで再エンコードしてから保存します。通常のJPEG / PNG / WebPに含まれるEXIF等のメタデータは、再エンコード時に引き継がれません。
- 新規画像は期限なしでKVに保存し、管理画面の「保存画像を完全削除」から明示的に削除します。削除すると活動写真・お知らせの参照も自動で外れます。
- 旧仕様で保存された画像には1年間のTTLが残っている場合があります。サイト情報・写真管理画面の「既存画像の保存期限を延長」を一度実行すると、既存画像も期限なしに切り替わります。
- リポジトリ内にある静的画像ファイルは、このWorkerの画像ストレージとは別管理です。

## お知らせ・年度別アーカイブ
- お知らせの保存・公開APIの上限を2,000件（JSONデータ10MB）に拡張しました。公開APIは公開中の記事を日付順に最大2,000件返し、年度別アーカイブが年度ごとに絞り込みます。
- 旧仕様の上限50件でKVに保存されなかった過去記事は、この変更だけでは復元されません。旧サイト・旧データ・手元の原稿などからの移行が必要です。現時点のKV内記事数・欠落状況は本番データを確認するまで断定しません。

## Search Console・robots.txt
- このサイトはGitHub Pagesのプロジェクトサイト形式で、公開URLに `/Meiji-HarmonicaSociety-website/` が含まれます。そのため、このリポジトリ直下の `robots.txt` は `https://hamosositemeiji.github.io/Meiji-HarmonicaSociety-website/robots.txt` に配置され、ホスト直下の `https://hamosositemeiji.github.io/robots.txt` にはなりません。
- Googleのrobots.txt仕様では、robots.txtは対象ホストのルートに置く必要があります。プロジェクトサイト内のrobots.txtはGoogleのホスト全体向けクロール制御としては機能しません。
- 現在のサイトマップは `https://hamosositemeiji.github.io/Meiji-HarmonicaSociety-website/sitemap.xml` です。Search Consoleでは、URLプレフィックスプロパティを `https://hamosositemeiji.github.io/Meiji-HarmonicaSociety-website/` に合わせ、そのプロパティの「サイトマップ」から上記の完全URLを直接送信してください。
- `Couldn't fetch` の原因はrobots.txtの配置だけでは断定できません。公開後にブラウザでサイトマップURLがHTTP 200で取得できること、XMLが正しいこと、Search ConsoleのプロパティURLが一致していることを個別に確認してください。
- ホスト直下のrobots.txtが必要な場合は、`hamosositemeiji.github.io` というユーザーサイト用リポジトリを別途用意するか、独自ドメインを設定する必要があります。現時点では既存のユーザーサイト用リポジトリが確認できなかったため、新規作成はしていません。

## バックアップと復元
- 管理画面トップの「データのバックアップ・復元」から、サイト情報・お知らせ・アップロード画像を1つのJSONファイルに書き出せます。
- バックアップは運営担当者が定期的にダウンロードし、アクセス制限された安全な場所に保管してください。ファイルには公開予定の部員情報・画像も含まれるため、公開リポジトリや共有リンクに置かないでください。
- 復元はバックアップ内の画像を先に登録し、サイト情報・お知らせを最後に置き換えます。既存の画像データは自動削除せず、バックアップに含まれない画像は残します。
- サイト情報・お知らせの保存前には直前のデータをKV内に90日間保存し、各種類の直近20件を保持します。
- 同じデータを複数の管理画面で編集した場合、古い画面からの保存はrevision conflictとして拒否します。Cloudflare KVには原子的なcompare-and-swapがないため、同時刻に重なった保存を完全に直列化するものではありません。複数人で同時編集せず、保存担当を1人に決めてください。

## 年度更新
1. 新年度用の `ADMIN_PASSWORD` と `SESSION_SECRET` をWorkerのSecretsで更新します。
2. これにより旧パスワードでの新規ログインが拒否され、旧セッションも無効になります。
3. 新パスワードは別経路で現役運営メンバーに共有し、退任者に共有しないでください。

## 注意
- Workerのソースコードは公開リポジトリに置いても構いませんが、パスワード、セッション秘密値、APIトークンは絶対に書き込まないでください。
- `admin/worker.js` を更新した場合は、Cloudflare DashboardからWorkerのコードを最新内容に置き換えて再デプロイしてください。GitHubへのコミットだけではCloudflare上のWorkerは更新されません。
- `admin/site-content.html` の保存先はKVの管理用領域です。公開サイトへの反映は公開読み出しAPIとサイト側の表示処理に依存します。保存後は公開ページで表示を確認してください。
- 問い合わせは公式サイトに掲載している連絡先へのメールで受け付けます。管理画面内に問い合わせ受信箱はありません。
- Cloudflareの無料枠・仕様は変更されることがあります。最新の制限は公式ドキュメントを確認してください。
